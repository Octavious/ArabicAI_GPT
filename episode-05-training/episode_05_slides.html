prepare_data.py — the conversion

From 2 million stories to one binary stream

# Load the Episode 2 tokenizer tokenizer = Tokenizer.from_file( "tinystories_tokenizer.json") # Load the dataset from Hugging Face dataset = load_dataset( "roneneldan/TinyStories") # Tokenize every story, concatenate all_ids = [] for story in dataset['train']: ids = tokenizer.encode(story['text']).ids all_ids.extend(ids) # Save as flat uint16 binary arr = np.array(all_ids, dtype=np.uint16) arr.tofile('train.bin')
↻
Run once. Tokenization never changes — do it once, then every training run just reads the .bin files.
≡
One flat stream. All stories concatenated end-to-end. A random window may cross a story boundary — the model learns that as just another pattern.
Why binary and not text? A flat uint16 file can be memory-mapped — that's what lets the data loader read random slices without loading the whole file.

data_loader.py — memory-mapping

Treat a 1 GB file like an array — using no RAM

# np.memmap opens the file WITHOUT # loading it into RAM. The OS pages in # only the bytes we actually touch. data = np.memmap( path, dtype=np.uint16, # must match Episode 2 mode='r' ) # Pick batch_size random windows max_start = len(data) - block_size - 1 starts = torch.randint( 0, max_start, (batch_size,) )
💾
uint16 — 2 bytes per token, holds 0–65,535. Plenty for our 4,096 vocab. Must match what Episode 2 wrote.
🎲
Random windows — each step grabs 32 random 256-token slices. The model never sees the data in order.
We re-open the memmap every batch — a known quirk where one long-lived memmap slowly leaks memory over a long run.
data_loader.py — the target shift

Why y is just x shifted by one

# The model predicts "the next token." # So the answer for each position is # simply the token that comes after it. x = data[i : i + block_size] y = data[i + 1 : i + block_size + 1] # Example: # data = [The, cat, sat, on, the, mat] # x = [The, cat, sat, on ] # y = [cat, sat, on, the] # # "after The -> cat", "after cat -> sat"
→
x is the input sequence the model reads.
→
y is the same sequence shifted left by one — every position now holds its own correct next token.
✓
No labels to create by hand. The text labels itself — this is what "self-supervised" means.

train.py — the core loop

Five steps, repeated 25,000 times

for step in range(MAX_STEPS): # 1. get a batch of real text x, y = loader.get_batch('train') # 2. forward pass + loss logits, loss = model(x, y) # 3. backward pass optimizer.zero_grad(set_to_none=True) loss.backward() # 4. clip gradients clip_grad_norm_(model.parameters(), 1.0) # 5. update the weights optimizer.step()
2
Forward — runs all 9 steps from Episode 3, returns the loss because we passed targets.
3
Backward — computes how each of the 12M parameters contributed to the error. zero_grad first because PyTorch accumulates.
5
Update — the optimizer nudges every parameter toward "less wrong." This is the actual learning.
train.py — the optimizer

AdamW — adaptive steps + weight decay

optimizer = torch.optim.AdamW( model.parameters(), lr=LEARNING_RATE, weight_decay=0.1, betas=(0.9, 0.95), ) # Adam part: each parameter gets its # own adaptive step size, based on a # running average of its gradients. # # W part: weight decay gently pulls # weights toward zero (regularization).
A
Adam — tracks momentum and variance per parameter. Parameters with consistently large gradients take smaller, more careful steps.
W
Weight decay — pulls weights toward zero. A regularization that reduces overfitting.
AdamW is the standard optimizer for transformers. Used in GPT-2, GPT-3, LLaMA, and nearly every modern model.
train.py — learning rate schedule

The learning rate is not constant

def get_learning_rate(step): # Phase 1: linear warmup if step < WARMUP_STEPS: return LR * (step+1) / WARMUP_STEPS # Phase 2: cosine decay progress = (step - WARMUP_STEPS) / (MAX_STEPS - WARMUP_STEPS) cosine = 0.5 * (1.0 + cos(pi * progress)) return MIN_LR + cosine * (LR - MIN_LR)
~0
→ warmup →
3e-4 peak
→ cosine →
3e-5
1
Warmup (steps 0–1000) — ramps up gently. Large updates on random initial weights would destabilize training.
2
Cosine decay (1000–25000) — big steps early for fast progress, small steps later to settle into a good solution.
train.py — validation

Check loss on data the model never trains on

@torch.no_grad() def estimate_loss(model, loader): model.eval() for split in ['train', 'val']: losses = torch.zeros(EVAL_BATCHES) for i in range(EVAL_BATCHES): x, y = loader.get_batch(split) _, loss = model(x, y) losses[i] = loss.item() results[split] = losses.mean() model.train() return results
T
Train loss — how well the model fits the data it sees.
V
Validation loss — how well it generalizes to data it never trained on.
If train loss drops but validation loss stalls or rises — that's overfitting. The model is memorizing, not learning.
Two concepts to recognize on sight

Underfitting vs Overfitting — the student analogy

U
Underfitting — the model is too dumb. Hasn't learned enough yet.
Like a student who didn't study. Fails practice AND real test.
Signs: both train and val loss are high.
Cure: train longer, bigger model.
O
Overfitting — the model memorized the training data.
Like a student who memorized the practice test. Aces practice, fails the real one.
Signs: train loss low, val loss stalls or rises.
Cure: stop training, more data, dropout.
✓
Healthy — the model is learning real patterns.
Like a student who actually studied. Does well on both tests.
Signs: train and val loss drop together, stay close.
On TinyStories (485M tokens) our 12M model is unlikely to overfit in 25,000 steps. But on smaller datasets or bigger models, this is the most common failure.
train.py — checkpointing

Save the model — but only when it improves

if losses['val'] < best_val_loss: best_val_loss = losses['val'] checkpoint = { 'model': model.state_dict(), 'optimizer': optimizer.state_dict(), 'config': config, 'step': step, 'val_loss': best_val_loss, } torch.save(checkpoint, 'checkpoint.pt')
☑
Only on improvement — if training later goes bad, the saved checkpoint is still the best version the model ever reached.
💾
Saves weights, optimizer state, and step number — everything needed to resume training later.
